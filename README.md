一台机器要把人声变成文字，中间隔着两个物理事实：声音随距离衰减，噪声随环境增长。
前者让远处的话筒信号跌进量化噪声，后者让近处的语音被空调和风扇掩蔽。绝大多数语音识别
系统的错误，不是模型不够大，而是这两个事实在进入模型之前就已经把信息损毁了。

HAE-NSG 处理的就是这一段。它不接受「先降噪、再放大」的常规流水线，因为那个顺序在数学上
有一个无法回避的缺陷。它把增益与噪声抑制放到同一个判决里结算，让放大倍数只对语音生效，
而底噪的绝对电平**永远不会因为放大而上升**。

纯 numpy 实现。无模型、无训练、无外部依赖。3 秒音频 0.5–1.5 毫秒，比 ASR 推理快两到三个数量级。

```python
import hae_nsg

audio, rate = hae_nsg.read_wav("meeting.wav")
out = hae_nsg.process(audio, "far", rate=rate)      # 远场预设
hae_nsg.write_wav("meeting_clean.wav", out, rate)
```

## 问题：为什么「先降噪再放大」注定失败

设输入信号为 $x = s + n$，其中 $s$ 是语音、$n$ 是底噪。常见流水线依次做两件事：

1. 降噪算子 $D$：把判决为噪声的帧乘以 $\alpha$（典型取 0.3）
2. 增益算子 $G$：把整体乘以 $k$（远场常见 $k = 20 \sim 120$）

如果有人声的帧全部被正确判决，输出是干净的。但判决从来不是完美的。设漏判率为 $\epsilon$，
则保留下来的底噪功率为：

$$
P_n' = (1 - \epsilon)\alpha^2 P_n + \epsilon P_n
     = P_n\left[\alpha^2 + \epsilon(1 - \alpha^2)\right]
$$

放大之后变成：

$$
P_{out} = k^2 P_n\left[\alpha^2 + \epsilon(1-\alpha^2)\right]
$$

代入 $\alpha = 0.3$、$k = 20$、$\epsilon = 0.1$：

$$
P_{out} = 400 \cdot P_n \cdot [0.09 + 0.091] = 72.4\,P_n
$$

底噪功率变成输入的 72 倍，即**净升高 18.6 dB**。而在只看「降噪环节」的测量口径下，这个
系统报告的是「底噪降低了 10.5 dB」。测量与听感彻底背离，原因就在这里——**放大是线性的，
它不知道哪个样本是人声**。

这个缺陷不是调参能解决的。$\epsilon$ 永远大于零，因为任何基于能量的判决都会在
「轻声辅音」与「较响噪声」之间出错。要解决它，必须让放大本身带上判决信息。

---

## 方法：判决与结算分离

HAE-NSG 把处理拆成两个层次：

**判决层**只在帧级别回答一个问题：这一帧是不是静音？答案是一个布尔掩码，不是一组增益。
**结算层**拿着这份掩码统一算账：

$$
y[i] =
\begin{cases}
x[i] \cdot k, & \text{语音帧} \\[4pt]
x[i] \cdot \dfrac{\alpha}{\max(k,\,1)}, & \text{静音帧}
\end{cases}
$$

关键在于静音帧的系数：它不是 $1/k$（那样只能把底噪拉回原位），而是固定值 $\alpha$ 再除以
增益。这样静音段的**最终绝对倍数恒为 $\alpha$**，与 $k$ 完全无关：

$$
\frac{\alpha}{\max(k,1)} \cdot k = \alpha \quad (\text{当 } k \ge 1)
$$

于是无论把语音抬高 20 倍还是 120 倍，底噪都净降约 10.5 dB。增益与降噪在这里**互相解耦**，
而不是互相抵消。

判决本身用两簇一维聚类，而不是固定分位数。原因同样具体：帧能量的第 10 分位落在静音帧
自身的分布内部，用它当门限会把静音段**横切**成两半——一半压掉、一半漏掉。漏掉的那一半
随后被增益放大几十倍，正好复现上一节推导的失败模式。两簇聚类找到的阈值落在两个分布的
**之间**，而不是其中一个的内部。这个区别在安静房间里看不出来，在底噪起伏大的场景里是
决定性的。

## 设计原则

**一、中间精度不可省。** 所有运算走 float64，只在出口落回 float32。分位数、排序、插值公式
全部手写固定，不依赖任何「不同版本可能有差异」的实现。这不是洁癖：Python 版与
C++ 版两方必须在同一个输入上给出同一串数字，否则「逐位对拍」这件事根本无法成立。

**二、所有函数对脏输入安全降级。** 空数组、None、NaN、Inf、只有三个样本的碎片——原样返回或
安全降级，不抛异常。音频处理位于实时链路的关键路径上，一帧坏数据不该把整条流打断。

**三、只放大，不缩小。** `target_rms` 是目标而非强制。近场录音误用远场预设时，最多被多补
一点高频，不会被压小。缩小的决定权留给调用方——库不替它做主。

**四、预加重改频谱，不改电平。** 高频补偿出口会把电平缩回输入电平。如果它顺手把电平降了，
后面的增益就得用更大倍数去补，很容易一头撞到 `max_gain` 上，白浪费动态范围。

## 四个预设与实测数据

| 预设 | 适用场景 | 目标电平 | 增益上限 | 高频补偿 |
|---|---|---|---|---|
| `near` | 贴着电脑说话 | 0.12 | 6× | 无 |
| `far` | 四五米以上 | 0.22 | 40× | 有 |
| `aggressive` | 麦克风很远 / 说话很轻 | 0.38 | 120× | 有 |
| `denoise` | 只降噪，不改音量 | — | 1× | 无 |

合成信号实测（前半段语音叠底噪、后半段只有底噪，16 kHz）：

| 预设 | 有声段 | 底噪段 | 净改善 | 输出峰值 |
|---|---|---|---|---|
| `near` | +13.3 dB | −10.5 dB | **+23.8 dB** | 0.339 |
| `far` | +18.1 dB | −9.0 dB | **+27.1 dB** | 0.649 |
| `aggressive` | +21.7 dB | −8.7 dB | **+30.4 dB** | 0.742 |
| `denoise` | −0.3 dB | −10.5 dB | **+10.2 dB** | 0.071 |

「净改善」定义为有声段提升减去底噪段提升，正值表示人声离底噪更远了。峰值全部在 0.75 以下，
不会削顶。

在真实远场录音上（同一段音频走旧版「先降噪后放大」与新版同链路对照）：

| | 底噪 RMS 变化 | 语音 RMS 变化 |
|---|---|---|
| 旧流水线 | × 8.00 | × 15.6 |
| HAE-NSG | **× 0.37** | × 15.6 |

旧流水线把底噪放大了 8 倍，正是第一节推导的失败模式；新引擎在同样的语音提升量下把底噪
压到 0.37 倍。

> 以上是合成信号与受控对照的数字，反映算法本身的取舍，**不等于**真实场景下的识别率提升。
> 真实效果请用自己的录音跑一遍对比听感与识别结果。

## 安装与快速开始

```bash
pip install numpy

cd HAE-NSG-Core
pip install -e .
```

唯一依赖是 numpy。

### 作为库

```python
import numpy as np
import hae_nsg

# 从文件
audio, rate = hae_nsg.read_wav("in.wav")
out = hae_nsg.process(audio, "far", rate=rate)
hae_nsg.write_wav("out.wav", out, rate)

# 直接给数组（float32 / float64，单声道，范围 -1..1）
x = np.zeros(16000, dtype=np.float32)
y = hae_nsg.process(x, "near", rate=16000)

# 自定义参数
from hae_nsg import Profile
mine = Profile(name="custom", target_rms=0.30, max_gain=50.0,
               pre_emph=0.6, pre_emph_mix=0.38,
               gate_enabled=True, gate_frame_ms=20.0,
               gate_attenuation=0.25, limit_knee=0.88)
y = hae_nsg.process(x, mine, rate=16000)
```

`process` 返回新数组，不修改输入。

### 命令行

```bash
hae-nsg in.wav                          # 默认 far 预设，输出 in_nsg.wav
hae-nsg in.wav -o out.wav -p near       # 指定输出与预设
hae-nsg in.wav --ab -o ab.wav -p far    # 左右声道对照（左=处理前，右=处理后）
hae-nsg --print-profiles                # 列出所有预设
```

## 在 C++ 里使用

`include/hae_nsg.h` 是同一套算法的单头文件实现（C++17，不依赖 numpy，只依赖标准库）。
两边输出逐样本一致，`tests/run_parity.py` 会自动编译并验证。

```cpp
#include "hae_nsg.h"

std::vector<float> audio = /* 16 kHz 单声道 */;
auto out = hae::nsg::process(audio, *hae::nsg::profileByName("far"), 16000);
```

零依赖、无动态分配热点、无全局状态，可以直接放进嵌入式或实时线程。

## 参数参考

| 参数 | 作用 | 调大会怎样 |
|---|---|---|
| `target_rms` | 想把语音抬到多大 | 增益更大，同时更容易碰到 `max_gain` |
| `max_gain` | 增益硬上限 | 能救更小的声音，但极端情况下语音会被削 |
| `pre_emph` | 高频补偿强度（0–0.95） | 齿音更清楚，过大时声音发尖 |
| `pre_emph_mix` | 补偿混回原始的比例 | 同上，但更平缓 |
| `gate_frame_ms` | 噪声门的分析帧长 | 越长判决越稳，但对短促语音反应变慢 |
| `gate_attenuation` | 静音帧保留多少能量 | 越大底噪越响；太小会有「抽气感」 |
| `limit_knee` | 软限幅拐点 | 越小越不容易削顶，但大音量会被压 |

## 与现有方案的定位差异

这个库**不是**通用降噪器，定位很窄，也很明确。

| 方案 | 定位 | 代价 |
|---|---|---|
| **HAE-NSG** | 为 ASR 前置设计：抬语音 + 压静音段 | 不做频域降噪，稳态噪声压不掉 |
| 谱减法 / `noisereduce` | 频域稳态噪声抑制 | 需要噪声估计，容易产生音乐噪声；在语音上会削掉辅音 |
| RNNoise | 神经网络降噪 | 需要模型文件，CPU 开销大一个量级，48 kHz 原生 |
| WebRTC NS | 通话降噪 | 为 16 kHz 窄带通话调优，对 ASR 增益无帮助 |

项目最早版本试过谱减法，在真实录音上把信噪比从 15.5 dB 打到 3.83 dB——测量假象叠加语音
损伤。根因与完整数据写在 [docs/ALGORITHM.md](docs/ALGORITHM.md)。

选择逻辑很简单：问题是「背景一直有空调声」，谱减法更合适；问题是「人离得远、声音小、
VAD 抓不到」，这个库更合适。两者可以串起来用。

## 已知局限

- **不做频域降噪**。稳态噪声只能靠静音帧门限压掉一部分，语音段内部的噪声原样保留。
- **单声道**。传双声道会被当成单声道算，结果是错的。
- **假设 16 kHz 或 48 kHz**。其他采样率能用，但 `gate_frame_ms` 对应的帧长会变。
- **不能救回被削顶的录音**。输入峰值到 1.0 的素材，信息已经丢了。
- **不含 VAD**。整段所有帧都会被判断，静音与语音的划分基于能量，不是语义。

## 相关项目

Hearizon Audiology Engine 拆成两个独立模块，加一个把它们装进实际产品的应用：

| 项目 | 作用 |
|---|---|
| **HAE-NSG Core**（本项目） | 噪声抑制与增益：让声音听得清 |
| [HAE-VAD Core](https://github.com/eyru/HAE-VAD-Core) | 语音活动检测与切句：让句子切得准 |
| [Hearizon Sync](https://github.com/eyru/HearizonSync) | 实时字幕翻译软件，Python 实现 |
| [HearizonSync C.R.V.](https://github.com/eyru/HearizonSync-CRV) | 同一产品的 C++ 重写版 |

推荐链路：

```
麦克风 → HAE-NSG（本库）→ HAE-VAD → ASR → 翻译
```

先增益再切句，是因为小声音被抬起来之后，切句的能量门限才有意义。反过来先切句再增益，
远场说话会被直接判成静音丢掉。
